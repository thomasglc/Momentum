# Étape 1 de l'audit et calendrier par athlète — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Plus rien de faux ni de superflu dans l'app athlète, et une semaine courante calculée pour chaque athlète depuis sa date de course.

**Architecture:** La logique de calendrier, de texte et de format vit dans des modules purs testés (`utils/`). `trainingService` calcule le début du plan de l'athlète une fois, au chargement ; le store `training` expose l'état du plan (pas commencé, en cours, terminé). Les contenus figés (`phases.json`, `plan.json`) disparaissent au profit des données Directus.

**Tech Stack:** Vue 3, Pinia 2, Tailwind 3, Directus 11, `node:test`.

Spec : `docs/audit-ux-2026-10-02.md` (étape 1, action 2.0, décision 1 tranchée : calendrier par athlète). Plan condensé.

## Décisions de conception

- **Début du plan d'un athlète** = lundi de la semaine de course − (longueur du plan − 1) semaines. Il faut la date de course **et** `plans.total_weeks` ; sinon on retombe sur `plans.start_date`. L'app reste donc correcte tant que le champ n'existe pas en prod.
- **Deux longueurs** : `totalWeeks` (longueur du plan, pour le calendrier) et `lastWeek` (dernière semaine écrite, pour la navigation). Le plan solo a 8 semaines écrites sur 19.
- **Noms de phases** : `plans.phase_names` (JSON `{ "1": "Force", … }`), sinon les noms par défaut.
- **Onglet Phases** : phases et semaines lues dans Directus, avec leurs dates et la semaine du jour. Le texte éditorial figé (objectifs, structure jour par jour) est retiré.
- **Solo** : `open_solo` vaut pour les deux genres ; c'est le genre du profil qui décide des allures et des repères affichés.
- **Texte** : note de semaine et conseil du coach coupés à deux lignes, dépliés au toucher ; notes d'exercice en pastilles ; l'alternative d'un exercice (note du catalogue) passe dans sa fiche.

## Interfaces

```js
// src/utils/planCalendar.js
todayIso(now)                       // date locale 'YYYY-MM-DD'
addDays(iso, n), mondayOf(iso)
planStartFor({ raceDate, totalWeeks, planStartDate })   // → iso | null
weekDates(startDate, weekNumber)    // → { startDate, endDate }
planStatus({ startDate, totalWeeks, raceDate }, today)
  // → { status: 'before'|'running'|'done', weekNumber, daysToStart, daysToRace }
groupPhases(weeks, startDate, nameOf)
  // → [{ id, name, firstWeek, lastWeek, startDate, endDate, weeks: [{ number, theme, isDeload, startDate, endDate }] }]

// src/utils/text.js
noteChips(note)      // "6-8 reps · RIR 2" → ["6-8 reps", "RIR 2"]
isLong(text, max)    // au-delà de max caractères (90 par défaut)

// src/utils/audience.js
audienceFor(planType, gender)   // → { isSolo, isDuoMixte, showLui, showElle }

// src/utils/stations.js
stationFacts(station, { isSolo, gender })   // → { volume, weight }

// src/utils/workout.js
parseClock("48:30")  // → 2910 ; invalide → null
```
